Command Line Lab

The first lab, and the only one with no C code at all. The goal is to get you fluent enough in a Linux terminal — navigation, tab completion, environment variables, a command-line editor — that every later lab's setup instructions stop being an obstacle. It ends with a self-contained shell challenge: a compressed archive you have to unpack and work through using nothing but man pages and the commands you just practiced.

Tested on: not exam content itself, but this is the toolchain (terminal, gdb, objdump) every later lab and the Bomb/Attack labs assume you already have.
Official lab page: This primer covers the concepts — for exact CAEDM setup steps, starter code, and the TA pass-off checklist, use the official page: byu-cpe.github.io/ecen224/labs/02_command-line.

Learning objectives

  • Navigate a Linux directory tree using only the terminal, with no file-browser GUI
  • Use tab completion, command history, and in-line command editing to work efficiently
  • Set, read, and list environment variables
  • Create and edit a text file with a command-line editor (nano, vim, or emacs)
  • Use man pages to figure out flags for unfamiliar commands (tar, chmod) instead of guessing or searching the web

1. Why terminal-only, on purpose

The lab explicitly bans file-browser apps and VS Code's file panel for this exercise: "that defeats the purpose of learning the command line." That's not arbitrary strictness — once you're reverse-engineering the Bomb Lab binary or debugging over an SSH session to a CAEDM machine with no GUI at all, a file browser won't be there to fall back on. This lab front-loads that dependency so it's not a surprise later.

2. Core commands and shortcuts

  • New terminal: Ctrl+Alt+T
  • Recall a previous command: ↑ / ↓, then edit it in place with ← / → and backspace before hitting Enter
  • Tab completion: partial path or command name, then Tab — a single match completes it, multiple matches list the candidates
  • Environment variables: export VAR=value sets one, echo $VAR reads one, env lists all of them; $SHELL, $USER, and $HOME are set for you already
nano keybindings (the simplest of the three suggested editors): Save Ctrl+O, Exit Ctrl+X, Cut a line Ctrl+K, Paste Ctrl+U, Search Ctrl+W. vim and emacs are more powerful but have a steeper learning curve — pick whichever you'll actually practice with the other labs.

3. The shell challenge

Part 2 is a self-contained puzzle: a challenge.tar.xz file that's compressed twice — once with tar, once with xz — that you need to decompress in a single command, then work through multiple levels using only what README.txt and man pages tell you. Two lookups you'll specifically need:

  • man tar — find the flag that extracts an archive, and the flag that names which file to extract
  • man chmod — find the flag/mode that makes a script executable

The point isn't memorizing tar xJf as a magic incantation — it's building the habit of reading a man page under time pressure and pulling out exactly the two flags you need, which is the same skill you'll use reading gdb's and objdump's much longer man pages later in the semester.

4. Skills you'll need

None — this lab has no lecture-module prerequisite. It's the foundation every later lab (and the Bomb/Attack labs) assumes you already have.

You type mk and press Tab, and the terminal lists several commands (mkdir, mkfifo, mknod, ...) instead of completing anything. What does that mean?
Tab completion only auto-fills when there's exactly one match. When several commands or files share a prefix, listing them is the shell's way of asking you to type a few more disambiguating characters.
You need to know which tar flag extracts an archive, but you don't remember it. What's the intended approach for this lab?
The shell challenge is explicitly designed to make you practice reading man pages to find flags yourself — the exact skill you'll lean on for gdb and objdump later, where nobody will hand you the flags.
