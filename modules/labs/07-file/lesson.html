File Lab

You take the menu system from the Display lab and point it at the filesystem: scan a folder, filter entries down to .bmp and .log files, list up to 8 of them on the LCD, and render whichever one the user selects — an image or the start of a log's text. This is the doorbell's photo/log viewer, and the first lab where you're reading directory structure, not just a single file.

Tested on: not exam-tested directly, but FILE * streams, buffers, and resource cleanup are the same C I/O material Module 07 covers and Game 1 tests.
Official lab page: This primer covers the concepts — for exact CAEDM setup steps, starter code, and the TA pass-off checklist, use the official page: byu-cpe.github.io/ecen224/labs/07_file.

Learning objectives

  • Distinguish a directory stream (DIR *) from a file stream (FILE *)
  • Iterate a directory's entries with opendir()/readdir()/closedir() until the NULL sentinel
  • Filter filenames by extension using strncmp() against d_name
  • Read file contents into a fixed-size buffer with fopen()/fread()/fclose()
  • Structure a growing program into independent functions instead of one long main()

1. Two different kinds of "stream"

It's easy to conflate these because both are opaque pointer types you get from an open call and must explicitly close, but they represent different things:

TypeRepresentsOpened withIterated/read withClosed with
DIR *An ordered list of a directory's entriesopendir()readdir() → struct dirent *closedir()
FILE *A position within one file's contentsfopen()fread()fclose()

readdir() returns a struct dirent * each call; its d_name field is the filename (a plain char array, same string-handling rules as Module 09). When there's nothing left, readdir() returns NULL — the loop terminator. Every entry it returns, filtered or not, includes things you don't want (like . and ..), which is exactly why filtering by extension is a required step, not an optional cleanliness pass.

2. The three functions

FunctionWhat it does
get_entries()Scans the folder, keeps only .bmp/.log names via strncmp() on the file extension, fills an entries array (capped at 8), returns the count found.
draw_menu()Reused from Lab 06 — renders the (now dynamically populated) entries array as a menu.
draw_file()Opens the selected file; for a .bmp, displays the image for 2 seconds; for a .log, reads and shows the first 100 characters of text for 2 seconds; then redraws the menu with the same item still highlighted.
Design note carried from the official lab: write get_entries, draw_menu, and draw_file as independent functions rather than inlining their logic into main(). The lab explicitly frames this as avoiding technical debt — Lab 08 and the final doorbell project keep adding features on top of this same file, and tightly coupled code makes each addition harder than the last.

3. Skills you'll need

  • Module 07 — C I/O: this lab is that module's printf/scanf material extended to file streams instead of stdin/stdout.
  • Module 10 — C Pointers: DIR * and FILE * are both opaque pointers you pass around and must not use after closing.
  • Lab 06 — Display: hard prerequisite — draw_menu and the button-driven selection loop are reused directly, not rebuilt.
readdir() is being called in a loop to list a directory's contents. How does the loop know when it's out of entries?
readdir() is a sentinel-terminated iterator: keep calling it and processing the returned struct dirent * until it hands back NULL. The 8-entry cap is a separate display limit applied while filtering, not how the underlying iteration itself terminates.
