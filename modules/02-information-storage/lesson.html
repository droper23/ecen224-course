Information Storage

Every piece of data on a computer, no matter what it represents, is ultimately just bits. This module covers how those bits are grouped into bytes, written compactly in hex, ordered in memory (byte order is one of the most exam-tested ideas in the whole course), addressed via pointers, and manipulated directly with bitwise operators in C.

Learning objectives

  • Convert values between decimal, binary, and hexadecimal by hand
  • Explain why hexadecimal is used as shorthand for binary, and convert between them digit-by-digit
  • Determine the byte-level layout of a multi-byte value in both big-endian and little-endian order

1. Bits, bytes, and why bits at all

Every bit on a computer is either 0 or 1, and all data on a computer — numbers, strings, images, instructions — is ultimately nothing but bits. What gives those bits meaning is entirely how they're interpreted: the same bit pattern can be a number, a character, or part of an image, depending purely on context. Eight bits are grouped into one byte, which is the basic addressable unit of memory on virtually every modern machine.

Bits exist because computers can only reliably distinguish two physical states, not ten. A wire or transistor sitting near 0.0–0.2V reads as a 0, and one sitting near 0.9–1.1V reads as a 1; anything in between is ambiguous and unreliable to detect. A base-2 (binary) representation maps directly onto "on" and "off," which is why binary is the native representation of digital hardware even though humans think in decimal.

2. Number bases: decimal, binary, hexadecimal

To help humans, we display the same underlying bits in different bases. The key idea behind any positional number system is that each digit's value depends on its position: in base b, the digit n places left of the point is worth digit × bn, and n places right of the point is worth digit × b-n. For example, 5132.1310 means 5×103 + 1×102 + 3×101 + 2×100 + 1×10-1 + 3×10-2. The exact same idea applies in binary: 101011.112 equals 1×25 + 0×24 + 1×23 + 0×22 + 1×21 + 1×20 + 1×2-1 + 1×2-2 = 32+8+2+1+½+¼ = 43.7510.

In binary, the leftmost digit is the most significant bit (MSB) and the rightmost is the least significant bit (LSB). Writing long strings of 1s and 0s by hand is tedious and error-prone, so we use hexadecimal (base 16) as a compact shorthand: since 16 = 24, exactly one hex digit encodes exactly 4 bits, so you can convert between binary and hex one nibble at a time without doing any arithmetic. 0FA1D37B16 is shorthand for the 32-bit pattern you'd get by expanding each hex digit into its own 4-bit binary group. In C, hex literals use the 0x prefix: 0x0FA1D37B or the case-insensitive 0x0fa1d37b.

Why is hexadecimal specifically base 16, rather than, say, base 8 or base 32, chosen as binary shorthand?
Any power of 2 works for this trick (octal, base 8 = 2^3, works too), but base 16 is the sweet spot for byte-oriented machines: since a byte is 8 bits and 8 is a multiple of 4, exactly two hex digits represent one full byte cleanly.

3. Sizes of C data types

Programs need to store numbers, and every variable is given a fixed number of bytes — which is exactly why every integer type in C has a limited range instead of being able to grow arbitrarily large. Typical sizes (in bytes) on 32-bit and 64-bit x86-64 systems:

C type32-bit64-bit x86-64

long48

Notice that long and pointers change size between 32-bit and 64-bit systems, but int, float, and double don't — a common source of portability bugs when code assumes a pointer fits in an int.

4. Strings as bytes

Text is stored using a character encoding that maps each character to a byte value. This course uses ASCII (American Standard Code for Information Interchange), where each printable character maps to one byte. The string "Hello world!" is stored, byte by byte in hex, as 48 65 6C 6C 6F 20 77 6F 72 6C 64 21. Because a string's length isn't stored alongside it in C, the language needs a way to mark where the string ends: a null terminator, a single 0x00 byte, written as \0 in C source. So "Hello world!" is actually 13 bytes in memory, not 12 — the last one being the terminating 00.

5. Endianness: the order bytes sit in memory

A multi-byte value like a 16-bit 1731310 (0x43A1) spans more than one memory address, and something has to decide which byte goes at the lower address. There are exactly two conventions:

  • Big-endian: the most significant byte is stored at the lowest address — 0x43 then 0xA1. This reads left-to-right the way humans naturally write numbers, and it's the standard byte order for network protocols.
  • Little-endian: the least significant byte is stored at the lowest address — 0xA1 then 0x43. Most modern CPUs (x86, x86-64) use this form natively.

Usually you never need to think about this — the compiler and CPU handle it consistently for you. But it becomes directly visible whenever you inspect raw memory (in a debugger, a memory dump, or by reinterpreting a pointer), or whenever data crosses between machines with different native byte orders (which is exactly why network protocols standardize on big-endian, often called "network byte order," so senders and receivers agree regardless of their own native endianness).

Worked example: the 32-bit hex value 0x12345678 stored starting at address 0x100:

Address0x1000x1010x1020x103
Big-endian12345678
Little-endian78563412
You dump raw memory on an x86-64 machine (little-endian) and see the bytes 78 56 34 12 at consecutive addresses starting from the lowest. What 32-bit hex value do those bytes represent?
Little-endian stores the least significant byte first (at the lowest address). Reading the bytes 78 56 34 12 from low to high address and reversing the byte order to reconstruct the value gives 0x12345678.

6. Addressing and pointers, at the byte level

Memory is just a huge array of bytes, and every byte has its own unique address. A pointer is nothing more than a variable that stores one of those addresses. When you declare int *p, the pointer itself occupies however many bytes a pointer takes on the target machine (4 on 32-bit, 8 on 64-bit x86-64, per the table above), and it holds the byte address where a 4-byte int begins. Dereferencing that pointer means the CPU reads the number of bytes appropriate to the pointer's type (4 bytes for an int *) starting at that address, then interprets those bytes according to the type and the machine's endianness. This is why pointer types matter even though addresses themselves are just numbers: the type tells the compiler how many bytes to read and how to interpret them.

7. Boolean algebra and bitwise operators in C

Underneath every higher-level operation, hardware implements four core boolean operations bit-by-bit: AND, OR, exclusive-or (XOR), and NOT. C exposes these directly as bitwise operators that operate independently on every bit of their operands:

OperationC operatorExample (A = 0110 1001, B = 0101 0101)
AND&A & B = 0100 0001
OR|A | B = 0111 1101
XOR^A ^ B = 0011 1100
NOT~~B = 1010 1010

These are easy to confuse with C's logical operators — &&, ||, and ! — which are a completely different operation. In C, the value 0 is false and every other value is true; a logical operator always produces exactly 0 or 1, treating its entire operand as one true/false value rather than operating bit-by-bit. Logical operators also short-circuit: && and || stop evaluating as soon as the result is already determined. Given A = 105, B = 85, C = 75: A > B && B > C evaluates to true and stops after confirming A > B is already enough combined with the short circuit rule to need the second check; A > B || B > C is true and stops after just the first comparison, since one true operand already makes an OR true. 

!0x41   // 0x00 (FALSE) — 0x41 is nonzero, so "not" it gives false
!0x00   // 0x01 (TRUE)  — 0x00 is already false, so "not" it gives true
!!0x41  // 0x01 (TRUE)  — double negation normalizes any nonzero to 1
0x69 && 0x55  // 0x01 (TRUE) — both operands are nonzero
0x69 || 0x55  // 0x01 (TRUE) — at least one operand is nonzero
What is 0x69 & 0x55 compared to 0x69 && 0x55?
& operates independently on each bit position (0x69 & 0x55 = 0x41). && treats each operand as a single true/false value — since both 0x69 and 0x55 are nonzero (true), the logical AND evaluates to 1 (TRUE), regardless of which specific bits are set.

8. Shift operators

C also provides shift operators, which move every bit in a value left or right by a given number of positions:

  • Left shift (x << y): shifts bits left y positions, discards the bits that fall off the left end, and fills with 0s on the right.
  • Logical right shift (x >> y for unsigned x): shifts bits right, discards bits that fall off the right end, and fills with 0s on the left.
  • Arithmetic right shift (x >> y for signed x): shifts bits right, but fills the left with copies of the original sign bit instead of 0s, so a negative number stays negative. This is what makes right shift on signed types equivalent to dividing by a power of 2 (rounding toward negative infinity) — a trick revisited in the Integer Arithmetic module.
x           = 0110 0010
x << 3      = 0001 0000
x >> 2 (logical)    = 0001 1000
x >> 2 (arithmetic) = 0001 1000   (same here — x is positive)

x           = 1010 0010
x << 3      = 0001 0000
x >> 2 (logical)    = 0010 1000
x >> 2 (arithmetic) = 1110 1000   (sign bit replicated — x is negative)
