Official scope

Game 1 homework answer guide

Game 1 covers HW1–HW10: Information Storage through C Control Flow & Functions. It also includes the no-homework lecture material on debugging, linking, and introductory assembly.

How to use this: read a card, state the rule before looking at its answer, then use the targeted drills below. In every multiple-choice question, eliminate answers that use the wrong representation, confuse an address with a value, or assume undefined behavior has a predictable result.

HW1 Information Storage

Answer rules: a byte is 8 bits; four bits make one hex digit; convert by place value or by grouping binary in nibbles. The same bit pattern has no inherent meaning—the type/interpretation supplies it.

Must get right: 45 = 00101101, 173 = 10101101, 0xB7 = 183, Cat! = 43617421, and C strings include 00. Little-endian stores the least-significant byte first (0x7A3C becomes 3C7A); big-endian preserves 7A3C.

Wrong-choice traps: do not reverse individual bits for endianness—reverse bytes. &, |, ^, and ~ are bitwise; &&, ||, and !! return logical 0 or 1.

HW2 Integer Representations

Answer rules: unsigned values use ordinary binary; a w-bit two's-complement value with a leading 1 is negative: subtract 2w or invert-and-add-one. The signed range is -2w-1 through 2w-1-1.

Why choices fail: zero extension preserves an unsigned value; sign extension replicates the sign bit; truncation retains only low-order bits. A cast changes interpretation/width, not the stored bit pattern. Never call an all-ones pattern “-1” unless it is being interpreted as signed.

HW3 Integer Arithmetic

Answer rules: unsigned arithmetic is modulo 2w; signed overflow is undefined behavior in C. Check signed overflow when two same-sign operands produce a different-sign result. Left shift moves bits toward higher significance; right shift is logical for unsigned and commonly arithmetic for signed values on the course target.

Why choices fail: wrapping is guaranteed for unsigned, not signed. Promotion happens before most arithmetic: an unsigned char may become int, so u + 1 need not wrap until assigned back to a narrow unsigned type.

HW4 Floating Point

Answer rules: normalized IEEE-754 values are (-1)s × 1.fraction × 2exponent-bias; the leading 1 is implicit. Zero uses exponent and fraction of zero; denormals use exponent zero and no implicit leading 1; all-ones exponent denotes infinity or NaN.

Why choices fail: binary floating point cannot exactly encode most decimal fractions (including 0.1), so exact equality after arithmetic can fail. The fraction field is not the entire significand, and exponent bits are biased rather than a plain signed integer.

HW5 C Overview & Variables

Answer rules: preprocessing expands directives, compilation produces assembly, assembly produces object code, and linking resolves external symbols. Track type, scope, storage duration, and initialization separately. A local automatic variable is not initialized unless its declaration supplies a value.

Why choices fail: assignment is an expression, so if (x = 0) is legal but false; it is not comparison. A pointer-to-const (const int *p) protects the pointed-to object through that pointer, while a const pointer (int *const p) cannot be redirected.

HW6 C I/O

Answer rules: match each conversion to the actual argument: %d/%i for int, %ld for long, %zu for size_t, %c for a character, %s for a null-terminated character sequence, and %p for an address.

Why choices fail: scanf ordinarily needs an address (&x) so it can modify the object; an array name already decays to its first-element address for %s. sizeof("cat") is 4 because the terminating null byte counts.

HW7 C Operators

Answer rules: distinguish logical operators from bitwise operators. && and || short-circuit and yield 0/1; &, |, and ^ operate independently on every bit. Parenthesize mixed expressions instead of relying on remembered precedence.

Why choices fail: a post-increment's value is the old value, a pre-increment's value is the new value, and expressions that modify a scalar more than once without required sequencing (for example i = i++ + 1) are undefined—there is no portable numeric answer.

HW8 Arrays, Strings & Structs

Answer rules: arrays are contiguous; a[i] means *(a+i). A string is a character sequence ending in '\\0'. char s[] = "hi" allocates three elements, while a pointer to a literal is not a mutable character array.

Why choices fail: in most expressions an array decays to a pointer, so an array parameter cannot reveal the caller's full array size. Struct fields can have padding for alignment; do not assume sizeof(struct) is the sum of visible field sizes.

HW9 C Pointers

Answer rules: p is an address and *p is the object at that address. &x creates a pointer to x; writing *p changes x when p == &x. Pointer arithmetic advances by elements, not raw bytes.

Why choices fail: a null, uninitialized, or dangling pointer cannot be dereferenced. Returning the address of a local leaves a dangling pointer after the function returns. C is pass-by-value; a function changes a caller object only by receiving its address and writing through the pointer.

HW10 Control Flow & Functions

Answer rules: trace a for loop as initialize → test → body → update. In a switch, execution continues into the next case unless a break, return, or jump intervenes. A recursive function needs a reachable base case.

Why choices fail: an off-by-one answer usually counts the test after the final update incorrectly. Function arguments are copies, so modifying a parameter does not modify the caller. A function can return a value or modify data through a pointer; those are different mechanisms.

Also on Game 1 (no dedicated homework): use compiler warnings as evidence, distinguish compile-time from link-time failures, know that a linker resolves symbols across object files/libraries, and read the basic x86-64 conventions: registers hold operands, instructions use AT&T source-then-destination order, and assembly reflects operations on values and addresses.

What to be ready to do

  • Convert binary, hex, unsigned, and two’s-complement values.
  • Predict overflow, casts, shifts, bitwise operations, and IEEE-754 edge cases.
  • Trace C expressions involving arrays, strings, structs, pointers, scope, and control flow.
  • Read compiler errors/warnings and use the right gdb move.
  • Explain compilation, symbols, static vs. dynamic linking, registers, and AT&T operand order.
