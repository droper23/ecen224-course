Official scope

Game 1 homework answer guide

Game 1 covers HW1–HW10: Information Storage through C Control Flow & Functions. It also includes the no-homework lecture material on debugging, linking, and introductory assembly.

How to use this: read a card, state the rule before looking at its answer, then use the targeted drills below. In every multiple-choice question, eliminate answers that use the wrong representation, confuse an address with a value, or assume undefined behavior has a predictable result.

HW1 Information Storage

Answer rules: a byte is 8 bits; four bits make one hex digit; convert by place value or by grouping binary in nibbles. The same bit pattern has no inherent meaning—the type/interpretation supplies it.

Must get right: 45 = 00101101, 173 = 10101101, 0xB7 = 183, Cat! = 43617421, and C strings include 00. Little-endian stores the least-significant byte first (0x7A3C becomes 3C7A); big-endian preserves 7A3C.

Wrong-choice traps: do not reverse individual bits for endianness—reverse bytes. &, |, ^, and ~ are bitwise; &&, ||, and !! return logical 0 or 1.

HW2 Integer Representations

Answer rules: unsigned values use ordinary binary; a w-bit two's-complement value with a leading 1 is negative: subtract 2w or invert-and-add-one. The signed range is -2w-1 through 2w-1-1.

Why choices fail: zero extension preserves an unsigned value; sign extension replicates the sign bit; truncation retains only low-order bits. A cast changes interpretation/width, not the stored bit pattern. Never call an all-ones pattern “-1” unless it is being interpreted as signed.

HW3 Integer Arithmetic

Answer rules: unsigned arithmetic is modulo 2w; signed overflow is undefined behavior in C. Check signed overflow when two same-sign operands produce a different-sign result. Left shift moves bits toward higher significance; right shift is logical for unsigned and commonly arithmetic for signed values on the course target.

Why choices fail: wrapping is guaranteed for unsigned, not signed. Promotion happens before most arithmetic: an unsigned char may become int, so u + 1 need not wrap until assigned back to a narrow unsigned type.

HW4 Floating Point

Answer rules: normalized IEEE-754 values are (-1)s × 1.fraction × 2exponent-bias; the leading 1 is implicit. Zero uses exponent and fraction of zero; denormals use exponent zero and no implicit leading 1; all-ones exponent denotes infinity or NaN.

Why choices fail: binary floating point cannot exactly encode most decimal fractions (including 0.1), so exact equality after arithmetic can fail. The fraction field is not the entire significand, and exponent bits are biased rather than a plain signed integer.

HW5 C Overview & Variables

Answer rules: preprocessing expands directives, compilation produces assembly, assembly produces object code, and linking resolves external symbols. Track type, scope, storage duration, and initialization separately. A local automatic variable is not initialized unless its declaration supplies a value.

Why choices fail: assignment is an expression, so if (x = 0) is legal but false; it is not comparison. A pointer-to-const (const int *p) protects the pointed-to object through that pointer, while a const pointer (int *const p) cannot be redirected.

HW6 C I/O

Answer rules: match each conversion to the actual argument: %d/%i for int, %ld for long, %zu for size_t, %c for a character, %s for a null-terminated character sequence, and %p for an address.

Why choices fail: scanf ordinarily needs an address (&x) so it can modify the object; an array name already decays to its first-element address for %s. sizeof("cat") is 4 because the terminating null byte counts.

HW7 C Operators

Answer rules: distinguish logical operators from bitwise operators. && and || short-circuit and yield 0/1; &, |, and ^ operate independently on every bit. Parenthesize mixed expressions instead of relying on remembered precedence.

Why choices fail: a post-increment's value is the old value, a pre-increment's value is the new value, and expressions that modify a scalar more than once without required sequencing (for example i = i++ + 1) are undefined—there is no portable numeric answer.

HW8 Arrays, Strings & Structs

Answer rules: arrays are contiguous; a[i] means *(a+i). A string is a character sequence ending in '\\0'. char s[] = "hi" allocates three elements, while a pointer to a literal is not a mutable character array.

Why choices fail: in most expressions an array decays to a pointer, so an array parameter cannot reveal the caller's full array size. Struct fields can have padding for alignment; do not assume sizeof(struct) is the sum of visible field sizes.

HW9 C Pointers

Answer rules: p is an address and *p is the object at that address. &x creates a pointer to x; writing *p changes x when p == &x. Pointer arithmetic advances by elements, not raw bytes.

Why choices fail: a null, uninitialized, or dangling pointer cannot be dereferenced. Returning the address of a local leaves a dangling pointer after the function returns. C is pass-by-value; a function changes a caller object only by receiving its address and writing through the pointer.

HW10 Control Flow & Functions

Answer rules: trace a for loop as initialize → test → body → update. In a switch, execution continues into the next case unless a break, return, or jump intervenes. A recursive function needs a reachable base case.

Why choices fail: an off-by-one answer usually counts the test after the final update incorrectly. Function arguments are copies, so modifying a parameter does not modify the caller. A function can return a value or modify data through a pointer; those are different mechanisms.

Also on Game 1 (no dedicated homework): use compiler warnings as evidence, distinguish compile-time from link-time failures, know that a linker resolves symbols across object files/libraries, and read the basic x86-64 conventions: registers hold operands, instructions use AT&T source-then-destination order, and assembly reflects operations on values and addresses.
Full HW1 answer key — Information Storage (28 questions)

1. Certification: True.

2. A byte contains 8 bits: True. A bit is one binary digit; eight of them form the byte unit used for addressable character-sized storage.

3. A bit pattern's meaning depends on interpretation: True. The same bits can be an unsigned integer, two's-complement integer, characters, or part of a floating-point value.

4. 10110100 has MSB 1 and LSB 0 (choice C). The MSB is leftmost and the LSB is rightmost; choices A, B, and D misread one or both endpoints.

5. 45 = 00101101: 32+8+4+1.

6. 173 = 10101101: 128+32+8+4+1.

7. 01110110 = 118: 64+32+16+4+2.

8. 10100101 = A5: group as 1010=A, 0101=5.

9. 0x3E = 00111110; each hex digit is exactly four bits.

10. 0xB7 = 183: 11×16+7. 10110111 is its binary representation, not the requested decimal answer.

11. 250 = FA: 15×16+10.

12. 1101.101 = 13.625: 8+4+1+1/2+1/8.

13. 0x2D4C = 0010110101001100.

14. A long on the course x86-64 system uses 8 bytes (choice D); 1, 2, and 4 are widths of other common integer types.

15. ASCII 42 59 55 decodes to BYU.

16. ASCII Cat! is 43617421.

17. C string OK is 4F4B00. The required null terminator is one byte 00; adding 2E incorrectly inserts a period.

18. Little-endian 0x7A3C is 3C7A in increasing-address byte order: least-significant byte first.

19. Big-endian 0x7A3C is 7A3C: most-significant byte first.

20. 10110110 & 01101101 = 00100100; AND keeps only positions that are 1 in both operands.

21. 10110110 | 01101101 = 11111111; OR sets a position when either operand has 1.

22. 10110110 ^ 01101101 = 11011011; XOR sets positions where operands differ.

23. ~00110101 = 11001010; complement flips every bit in the stated 8-bit width.

24. 0xA6 & 0x3F = 26: A6=1010 0110, 3F=0011 1111.

25. 0x00 || 0x52 = 1. Logical OR returns a truth value, not the nonzero operand.

26. 0x34 && 0x00 = 0; the right operand is false.

27. !!0x80 = 1. The first ! converts nonzero to 0; the second negates it.

28. With an 8-bit result, 0x35 << 2 = D4: 00110101 shifts to 11010100; bits shifted past the width are discarded.

Full HW2 answer key — Integer Representations (24 questions)

1. Certification: True.

2. -37 as 8-bit two's complement is 11011011. Start with +37, 00100101, invert to 11011010, then add one. A leading 1 does not mean “negative magnitude”; it is part of the two's-complement encoding.

3. 0xB6, interpreted as 8-bit two's complement, is -74: 182 unsigned minus 256. Treating it as +182 ignores the requested signed interpretation.

4. 01101001 is 105; the leading 0 makes it nonnegative.

5. 10010110 is -106: unsigned 150 minus 256. Equivalently, invert/add one to get magnitude 106.

6. Negating 11001010 gives 00110110; complement then add one.

7. Negating 00011101 gives 11100011. Do not merely flip bits: that would be one's complement and is one too small.

8. 00110111 + 11011110 stores 00010101 in 8 bits; discard the carry beyond the width.

9. That stored result represents 21 signed. The operands are +55 and -34, so the arithmetic cross-check is 21.

10. 01011010 + 00110101 stores 10001111.

11. The addition in 10 has signed overflow: Yes. Two positive operands produced a bit pattern whose signed interpretation is negative; a carry-out is not the signed-overflow test.

12. 11100100 - 00010111 = 11001101 after adding the two's-complement negation of the subtrahend.

13. That result is -51: 205 unsigned minus 256.

14. 01110000 - 11110010 stores 01111110.

15. The subtraction in 14 has no signed overflow: 112 - (-14) = 126, which remains within -128 through 127.

16. -73 in 8-bit two's complement is 10110111.

17. +73 is 01001001.

18. -73 as 16 bits is 1111111110110111; sign extension copies the original leading 1.

19. Sign-extending 10101100 produces 1111111110101100. Copy the sign bit, rather than padding with zeroes.

20. Zero-extending that same unsigned pattern produces 0000000010101100. The bit pattern is now interpreted as 172, not as a negative value.

21. Casting signed char -45 to unsigned char gives 211: conversion modulo 256.

22. Reinterpreting unsigned char 240 as signed 8-bit gives -16; the bits are unchanged and 240 - 256 = -16.

23. A 10-bit two's-complement integer has minimum -512 (-2^9).

24. Its maximum is 511 (2^9-1).

Full HW5 answer key — C Overview & Variables (26 questions)

1. Certification: True.

2. A hosted C program begins by calling main: True.

3. #include <xyz.h> searches user include directories first: False. Angle brackets use the system/include-path search convention; quoted headers first consider the source's directory.

4. total and Total are different C identifiers: True; C is case-sensitive.

5. A void function returns no value: True.

6. An uninitialized local int count; is zero: False. Automatic local storage has indeterminate value until initialized.

7. The shown Hello World program compiles: False; it is missing the semicolon after printf.

8. int i, j = 6; initializes both variables: False. Only j receives 6; i remains uninitialized.

9. With the nested declaration, the first printed i is 5: the inner variable shadows the outer one.

10. After the inner scope ends, printed i is 6: the outer variable is visible again.

11. X1 is 10.

12. X2, defined as (X1 * 2), is 20.

13. After z = y = x = 8, x is 8.

14. y is 8.

15. z is 8. Assignment associates right-to-left and yields the assigned value.

16. In enum { Dog, Cat, Sheep = 4, Horse, Tiger }, Dog is 0.

17. Cat is 1.

18. Horse is 5; it follows explicitly assigned Sheep = 4.

19. Tiger is 6.

20. In enum level { Low=2, Medium, High=7, Critical }, Critical is 8.

21. With #define OFFSET 8 and #define SIZE OFFSET+2, char buffer[SIZE*2] has 12 elements: textual expansion gives 8 + 2 * 2, not (8+2)*2.

22. With #define PLUS1 x + 1, y = 5 * PLUS1 becomes 51: 5*x+1. Macros need protective parentheses.

23. ASCII character literal '1' has value 49, not numeric 1.

24. Parenthesized #define COUNT (BASE + 2), with BASE 6, makes COUNT*3 equal 24.

25. Unparenthesized #define COUNT BASE+2 makes COUNT*3 equal 12 after precedence: 6 + 2*3.

26. A copy initialized from n remains 9 after n later becomes 4; ordinary scalar assignment copies the value rather than creating an alias.

Full HW6 answer key — C I/O (12 questions)

1. Certification: True.

2. The sprintf(array, "%s", "hello there!") program prints hello there!. sprintf writes the characters plus the null terminator into array; %s prints that terminated string.

3. With input 25 9 2023, scanf("%d %d %d", ...) returns 3: all three conversions succeed.

4. For x=122, printf("%d",x) prints 122, its decimal representation.

5. printf("%x",x) prints 7a, the hexadecimal representation of 122.

6. printf("%c",x) prints z, the character whose code is 122.

7. To print 85%, use "%d%%\n". The first conversion consumes x; doubled %% emits one literal percent sign.

8. With format "%d/%d/%d" and input 25 9 2023, the return is 1. The first integer is read, then the literal slash is required and missing; whitespace in a format is not interchangeable with a slash.

9. With format "%d/%d/%f" and input 25 9 8.0, the return is 1 for the same missing-slash reason.

10. With "%d %d %f" and input 25 9 8, the return is 3. %f accepts an integer-looking token as the floating value 8.0.

11. With "%d %s %d" and input 25 9 2023, the return is 3. %s accepts 9 as a one-character string.

12. To print September 25, 2023, type 25 September 2023. The input order follows the conversion list—day, string month, year—not the output order.

Full HW7 answer key — C Operators (16 questions / 19 points)

1. Certification: True.

2. ((0>1) && (i=14)) prints 9. The left side of && is false, so it short-circuits and does not assign 14.

3. ((0>1) || (i=14)) prints 14. The false left side of || requires evaluation of the right side.

4. int i = 0 < 1; prints 1; relational operators produce integer truth values 0 or 1.

5. j++ prints 4, then increments j to 5.

6. The following ++j prints 6; prefix increment changes the object before yielding its value.

7. 0xF0 | 0xF == 0xFF prints 240. Equality binds tighter than bitwise OR, so it parses as 0xF0 | (0xF==0xFF) = 0xF0|0. Parentheses are required for the intended comparison.

8. (0xF0 | 0xF) == 0xFF prints 1 because the OR is 0xFF.

9. With i=5, !i is false, so the program prints True.

10. 5/1.4 is floating arithmetic, about 3.57, and assignment to int truncates toward zero: 3.

11. From w=x=y=z=5; v=2, the compound operations print 2 1 7 20: division, remainder, bitwise OR, then left shift respectively.

12. (a/b) ? a : b prints 3, because integer 3/2 is 1 (true), selecting a.

13. a - b/c*d + e*f prints 25: 5 - (5/5)*5 + 5*5 = 25. Multiplication/division precede addition/subtraction.

14. x *= y+1, for x=2 and y=5, makes x 12.

15. x = !y ? 3 : 2, with y=1, gives x 2; !1 is false.

16. 1 + 1 << 1 + 1 gives 8: additions bind before shift, yielding (1+1)<<(1+1).

Full HW9 answer key — C Pointers (31 questions)

1. Certification: True.

2–13. With x=237 at 0x1000, ptr1=&x, *ptr1=++x, and ptr2=&ptr1, the prints are: 2: ee; 3: 1000; 4: 1000; 5: ee; 6: 1004; 7: 1004; 8: 1000; 9: 1008; 10: ee; then after x += 1, 11–13: ef, ef, ef. The levels are the key: ptr1 is x's address, *ptr1 is x's value, ptr2 is ptr1's address, and **ptr2 reaches x again.

14–21. For 2-byte uint16_t A[5]={1,2,3,4,5} at 0x1000, ptr=A; ptr+=2; *ptr+=2, prints are: 14: 1000; 15: 1000; 16: 1002; 17: 1002; 18: 100A; 19: 1004; 20: 2; 21: 5. An array name decays to its first element's address; pointer increment advances by element size, so A+1 is two bytes later. *ptr+=2 changes A[2] from 3 to 5.

Full HW10 answer key — Control Flow & Functions (19 questions)

1. Certification: True.

2–4. Starting x=10, y=20, z=30, the if / else if chain leaves x=10, y=5, z=30. x<10 is false; x<20 is true, then the chain stops.

5–7. In the switch('a') with no breaks, the result is x=10, y=20, z=15. Case a increments y to 21 and multiplies z to 150, then falls through case b, decrementing y and dividing z by 10.

8–10. For for(x=1; x<y; x++,y--) z=x+y;, the final values are x=11, y=10, z=21. Trace test/body/update in that order; the final update occurs after the last body execution.

11–13. For while(!z) { z %= y; }, the final values remain x=10, y=20, z=30. Since z is nonzero, !z is false and the body never runs.

14–16. For do { x=--y; z=x++; } while(z);, final values are x=1, y=0, z=0. A do-while executes before its test and repeats until the assigned z becomes zero.

17–19. For if (x=y) y=100;, final values are x=20, y=100, z=30. This is assignment, not comparison: it assigns 20 to x, whose nonzero value makes the condition true.
